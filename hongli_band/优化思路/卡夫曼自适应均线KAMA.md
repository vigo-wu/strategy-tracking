## 卡夫曼自适应均线（KAMA）替代传统 MA
该方案属于“指标形态自适应”。不需要改变 20 或 60 这些周期数字，而是直接用一套具备动态弹性的算法线去替换原有的简单移动平均线（SMA）。
## 1. 核心评估指标：效率系数（Efficiency Ratio, ER）

* 计算方法：在设定的计算窗口内，将“这段时间的总方向位移（期末价 - 期初价）”除以“期间每天价格波动的绝对值总和（总行程）”。
* 指标含义：ER 接近 1 说明股票在单边大牛市中，爬坡极其顺畅；ER 接近 0 说明股票在横盘死水或反复拉锯中，全是噪声。

## 2. 动态平滑机制
KAMA 会根据 ER 的实时变化，利用非线性公式动态调整自身的平滑系数（Alpha）：

* 当红利股走出顺畅慢牛（ER 高）时：KAMA 自动切换为“快速均线”模式，指标线迅速贴近股价。一旦发生缩量回踩，能立刻在较高位置发出加仓信号，防止踏空。
* 当红利股陷入无量阴跌或横盘（ER 低）时：KAMA 自动切换为“极慢均线”（类似于走平的生命线）模式，指标线变得极其迟钝。此时股价即时跌破均线，算法也会判定当前属于震荡噪声，从而激活你策略中的 vol_dry_skip（无量阴跌禁开）或拦截买入，起到动态防御的作用。

为了在你的国金 QMT 终端模型（v1.44 骨架）中完美落地方案B（纯 Python 自定义 KAMA），我们需要将 Perry Kaufman 的数学公式转化为符合 QMT 运行机制、支持动态调参、且能与你的“共享账本”解耦的架构设计。
以下是具体的实现思路与架构设计说明：
------------------------------
## 核心算法的模块化封装
首先，不能在主循环里写面向过程的嵌套循环，必须将 KAMA 封装成一个纯粹的数学计算函数，放置在你的通用模块（如 scripts/qmt_common/ 或单独的 indicators.py）中。
## 1. 输入与输出设计

* 输入参数：
* close_series (Pandas.Series)：前复权的历史收盘价序列（单标的）。
    * er_period (int)：效率系数的计算窗口（默认 10）。
    * fast_period (int)：快线极限周期。例如日线低吸锚定 MA20，则设为 20。
    * slow_period (int)：慢线极限周期。例如日线低吸锚定 MA60，则设为 60。
* 输出数据：返回一个与输入对齐的 Pandas.Series，包含计算好的动态 KAMA 曲线。

## 2. 内部向量化计算流程
为了保证 14:56 尾盘成交窗（PENDING_EXEC）评估信号时模型的秒级响应，必须利用 Pandas 的向量化特性，避免在 Python 中使用耗时的 for 循环：

1. 位移与行程向量化：
* 用 .diff(er_period).abs() 瞬间算出全历史区间的净变动（Change）。
    * 用 .diff().abs().rolling(er_period).sum() 瞬间算出全历史区间的总波动（Volatility）。
    * 两者相除直接得到全量 ER 序列，缺失值用 0 填充。
2. 平滑系数矩阵化：
* 根据输入的 fast_period 和 slow_period 算出常数 $\text{SC}_{\text{fast}}$ 和 $\text{SC}_{\text{slow}}$。
    * 利用 Pandas 的广播机制，一行代码完成全量平滑系数 $\text{SC}_t = \left[ \text{ER} \times (\text{SC}_{\text{fast}} - \text{SC}_{\text{slow}}) + \text{SC}_{\text{slow}} \right]^2$ 的计算。
3. 迭代更新降噪：
* 由于 KAMA 的核心更新公式 $\text{KAMA}_t = \text{KAMA}_{t-1} + \text{SC}_t \times (\text{Price}_t - \text{KAMA}_{t-1})$ 具有前后依赖性，此处可使用 Numba 库的 @njit 装饰器或用高效的迭代器进行底层加速，确保暖机（取数预热）和实盘 Tick 推送时没有延迟。

## ⚙️ 二、 策略配置层（config.py）的适配解耦
在你的 hongli_band/scripts/qmt/hlband/config.py 中，需要用这套自定义 KAMA 彻底替换原有的固定均线常量。由于不同标的需要不同的快慢极限，我们要将配置升级为“动态参数生成器”。

1. 废弃传统 MA 周期：废弃原有的 W_MA_FAST/MID/LIFE/SLOW 等静态整型。
2. 引入 KAMA 参数三元组：在配置中为不同维度的均线定义 (ER周期, 快极限, 慢极限)。
* 日线快线（替代原 MA20 支撑位）：配置为 KAMA_DAILY_FAST = (10, 5, 20)。当趋势极强时，它会变成 5 日线贴紧股价；震荡时，放宽到 20 日线。
    * 日线慢线（替代原 MA60 强防线）：配置为 KAMA_DAILY_SLOW = (10, 20, 60)。
    * 周线生命线（替代原 MA34 过滤线）：配置为 KAMA_WEEKLY_LIFE = (5, 13, 34)。

------------------------------
## 🔄 三、 QMT 实盘运行时的动态调用架构
在 HlBand.py 主程序中，KAMA 的调用和更新需要遵循 QMT 的双频数据更新逻辑。

[QMT数据层调用]
│
├──► 周线级别 (获取周K线) ──► 调用自定义KAMA (5, 13, 34) ──► 产出周线生命线 ──► 进行 §一 周线过滤
│
└──► 日线级别 (获取日K线) ──► 调用自定义KAMA (10, 5, 20) ──► 产出日线快线 ──► 进行 §二 缩量回踩评估


1. 暖机期（历史数据准备）：
* 在策略初始化时，必须向 QMT 请求至少 slow_period * 4 长度的历史 K 线数据（前复权），以确保 KAMA 的初始值（SMA）能够通过足够的迭代次数完全收敛，消除初期噪声。
2. 周线过滤层（§一）的适配：
* 在周五或每日尾盘评估周线转空（weekly_bear）时，先将日线合成周线。
    * 将周线序列传入 KAMA 函数，计算出当前的动态周生命线值，代替原有的 MA34_W，进行高位乖离（w_bias_skip）和低位斜率（w_slope_skip）的拦截判定。
3. 日线低吸层（§二）的容差微调：
* 原本你的策略在买点处有容差设计：收盘靠近 MA20 或 MA60（容差 ±2.5%）。
    * 思路调整：因为 KAMA 在横盘时本身就会高度钝化并收敛于价格中轴，其“自带有序容差”。因此，在使用 KAMA 替换 MA20/60 后，原有的 MA_TOUCH_TOL = 0.025（2.5% 容差）可以适当收紧至 1.0% 或 1.5%，甚至直接要求“收盘价跌破 KAMA 快线但受到 KAMA 慢线支撑”，这样能过滤掉更多无量阴跌的废单。

## 🛠️ 四、 针对 v1.44 特殊机制的防错设计

1. 打卡时间同步性（BOOK_FREEZE）：
   KAMA 的计算完全在各标的独立的主图（单仓骨架）中完成。在 14:56:00 进入 BOOK_FREEZE_CLOSE 写入共享账本前，各图已经用最新的 KAMA 算好了买卖信号，完全不影响后端的均分（split）与水位法（MAX_NAME_FRAC）资金划拨。
2. 智能时间（time_force）的锚定切换：
   原本策略中 TIME_FORCE_BARS = D_MA_SLOW // 2（即 60/2 = 30天）。改用方案 B 后，由于慢线周期是一个固定参数（如 60），所以该时限依然可以稳定锚定在 slow_period // 2。
   但是，强制平仓的条件“破日线 MA60”必须同步变更为“收盘价有效跌破 KAMA_DAILY_SLOW”。由于 KAMA 慢线在熊市阴跌中走平得更快，这会使得你的“磨人仓”离场比传统 MA60 更加果断，能更早触发 time_force 保护资金。
