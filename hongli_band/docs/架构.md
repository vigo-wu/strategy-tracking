# HlBand 当前架构

给要改因子、Recipe 或 `_handle` 的维护者：本文说明信号如何从行情走到委托，以及改哪一层。

交易语义（买卖点、窗口、预算）仍以 [model.md](../model.md) 为准。布尔式叶子与 AST 细节见 [Recipe分类.md](./Recipe分类.md)。设计过程见 [架构优化.md](./架构优化.md)。

---

## 一句话

Factor Lib 只读 `ctx` 产出中性布尔；入场 / 出场 / 加仓 / 减仓各持一份 Recipe；`_resolve_intent` 仲裁成 Intent；`qmt_common` 只消费 Intent（pending / 下单）。因子和 Recipe **不下单**。

```text
OHLCV + STATE
      │
      ▼
 Feature/Ctx（算一次）
      │
      ▼
 Factor Lib（eval → bool）
      │
      ├── RECIPE_ENTRY      开仓
      ├── RECIPE_EXITS      按笔有序出场
      ├── RECIPE_SCALE_IN   加仓
      └── RECIPE_SCALE_OUT  减仓（默认关）
      │
      ▼
 Intent（flat > reduce > add > open）
      │
      ▼
 pending → passorder（qmt_common）
```

## 源码落点

片段在 `hongli_band/scripts/qmt/hlband/`。禁止片段互 `import`；靠 `_deploy_qmt_gbk.py` 的 `MODULE_ORDER` 拼接。`factors/lib/*.py`（跳过 `_` 前缀）由 glob 插入 registry/expr/ctx 之后、slots 之前。

| 层 | 文件 | 职责 |
| :--- | :--- | :--- |
| 配置 | `config.py` | `RECIPE_*`、阈值、面板 bind |
| 特征 | `indicators.py`、`factors/ctx.py` | 均线 / MACD / 量；组装只读 `ctx` |
| 注册 / 求值 | `factors/registry.py`、`factors/expr.py` | `_register_factor`、`_hit` |
| 原子 | `factors/lib/<id>.py` | 一文件一叶子，`eval(ctx)→(bool, detail)` |
| 四槽 | `factors/slots.py` | 评 Recipe、pending 闸门、按笔出场 |
| 仲裁 | `factors/intent.py` | `_resolve_intent`，不写 pending、不碰预算 |
| 仓位门槛 | `strategy.py` 的 `_scale_gate`、`budget.py` | `scale_once` / 满槽 / 金额；不是因子 |
| 执行 | `qmt_common` + `strategy.py` pending | 成交窗、T+1、lots |

改完跑：

```text
python hongli_band/scripts/qmt/_deploy_qmt_gbk.py
```

禁止手改 `qmt_terminal_hlband.py` 或 QMT `python\` 下 GBK 产物。

## ctx：行情 + 状态，算一次

`_build_factor_ctx` 产出：

```text
ctx = {
  market,   # 日/周序列与已算特征
  state,    # 成本、峰值、持仓日、当前 lot、周空 streak…
  clock,    # weekly_bear / weekly_bull 电平
  _tf_hook, # time_force 只读 eval 留下的写回钩，评完再 apply
}
```

约束：

- `eval` **只读** `ctx`。峰值、持仓日、除权在进因子前由运行时更新。
- 出场按笔：`_ctx_with_lot` 填 `state.lot` 再 `_hit`。无 lots 时 `_handle` 用 `_lot_from_agg()` 合成一笔，仍走 `_eval_lot_exits_recipe`。
- 现金、全池槽位、pending 超时 **不进** `ctx`。

`time_force` 的趋势让路写回走 `_apply_tf_hooks` → `_time_force_mark_skip`，不在 `eval` 里改 `A.*`。单测可继续调 `_time_force_hit`（内部会立刻写回）。

## 因子无立场

叶子是复合原子（与日志 reason 对齐），本身不决定买/卖。同一 id 可进多个槽，例如 `pullback_vol` 既在入场也在加仓。

`_register_factor(..., kind="gate"|"signal")` 里的 `kind` **不是槽归属**：`gate` 只表示 `not` 失败时的 skip 码要从入场 `real` 里剔除，避免把 `chase_skip` 当成开仓理由。

现网叶子清单与内部复合条件见 [Recipe分类.md](./Recipe分类.md) §7。

**不是因子**（留在仓位 / 执行层）：

- `BOOK_LOT_MAX` / `buy_cap` / `scale_cap` / `scale_once`
- `SCALE_ARM` / `SCALE_ARM_BARS` / `SCALE_W_HIST_MIN`（`_scale_gate`）
- T+1、当日加仓后跳过评卖（`skip_sell_eval_day`）
- pending 超时、成交窗

## 四槽 Recipe

真源是 `config.py` 的 `RECIPE_*`。空列表 `[]` = 该槽关闭。引擎支持任意 `and` / `or` / `not` 嵌套；**不要**把「入场必须 OR、出场必须 AND」写进代码。

| 槽 | 配置 | 现网默认 | 求值 |
| :--- | :--- | :--- | :--- |
| 入场 | `RECIPE_ENTRY` | `¬chase ∧ ¬vol_dry ∧ ¬w_bias ∧ ¬w_slope ∧ ¬weekly_bear ∧ pullback_vol` | `_eval_entry_slot`：整棵 `_hit`，`real` 去掉 gate skip |
| 加仓 | `RECIPE_SCALE_IN` | `¬weekly_bear ∧ ¬w_bias ∧ ¬w_slope ∧ ¬vol_dry ∧ (pullback_vol ∨ plat_break ∨ w_macd_golden)` | `_eval_scale_in_slot`；**无** `not chase` |
| 出场 | `RECIPE_EXITS` | `["stop_loss", "trail_stop", "time_force"]` | **有序列表**，每笔首个命中即停 |
| 减仓 | `RECIPE_SCALE_OUT` | `[]` | 非空且持仓 ≥2 笔时，按 `SCALE_OUT_LOT` 平 1 笔 |

求值规则（`_hit`）：

- `and` 短路（对齐旧代码：chase / vol_dry 先失败就返回）
- `or` 收集全部命中叶子（加仓日志能列出多个触发）
- `not` 失败时 reason 用 skip 码（`chase_skip`、`vol_dry_skip`…）

未知叶子直接 `ValueError`，不静默跳过。

## 仓位仲裁

`_handle` 先评四槽，再 `_resolve_intent`。优先级写死在函数顺序里：

```text
周空确认全平（force_empty ∧ RECIPE_EXIT_WEEKLY_BEAR）
  > RECIPE_EXITS 命中（flat，按笔）
  > RECIPE_SCALE_OUT（reduce，须 ≥2 笔）
  > 加仓（scale_in_hit ∧ _scale_gate）
  > 开仓（空仓 ∧ entry_hit ∧ real 非空）
```

Intent 只含目标与 reasons / lot_ids / shares，不写 `A.pending_*`、不算预算。`_handle` 再把它变成 `pending_entry` / `pending_exit`。

加仓还要过 `_scale_gate`（开关、已有仓、本轮只加一次、满槽、浮盈/持仓日/周柱）。执行日已有卖点则取消加仓 pending（`scale_sell_block`），让路出场。

## pending：粘性委托

已确认的买单隔夜仍有效，**不**要求信号叶子次日仍为真。否则 `pullback_vol` 次日熄灭会撤掉昨收确认单，默认成交变严。

`_pending_gate_hit(ctx, add)` 只复评对应槽里、位于顶层或 `and` 直接子节点的 `["not", leaf]`（不进 `or`、不做通用 AST 遍历）：

| pending | 复评哪份 Recipe 的 not |
| :--- | :--- |
| 开仓 | `RECIPE_ENTRY`（含 `chase`） |
| 加仓 | `RECIPE_SCALE_IN`（默认无 chase） |

任一 not 失败 → `pending_entry cancel`，`why` = skip 码。禁止 `_hit` 整棵入场/加仓式来撤单。

相对把闸门写死在 `_try_exec_pending_entry` 的旧逻辑，现网默认的**唯一**差异：开仓 pending 隔夜变成 chase 会撤。加仓默认不变。不要为「零差」再写死旧四门。

`_handle` 里 `_weekly_bias_guard` / `_weekly_low_slope_guard` 仍给状态行 prepend skip 码，与 pending 撤单无关。

## 周空是两路，不要并成一条

| 路 | 谁算 | 干什么 |
| :--- | :--- | :--- |
| 电平 | 因子 `weekly_bear`（读当日/当周空头） | 入场、加仓 Recipe 的 `not`；pending 闸门 |
| 确认全平 | `_update_w_bear_streak` → `force_empty` | 连续 `W_BEAR_CONFIRM_DAYS` 根信号日仍空才 `intent.flat`；受 `RECIPE_EXIT_WEEKLY_BEAR` 开关 |

Recipe 叶子回答「今天是不是空头」；streak 回答「要不要强制清仓」。不要把确认日数塞进 `eval`。

## 网格 / local_bt

格子可以 override `RECIPE_*`（JSON）。探针在改过 Recipe 时打 `recipe=` 指纹（四槽 + `RECIPE_EXIT_WEEKLY_BEAR`）。

扫参分两层：少数命名布尔变体，再扫已启用因子的数值。不要对全因子做 `2^n` 开关积。细则见 `qmt-local-bt-grid`。

「动态」= 部署/回测期按 Recipe 选用**已编进包**的原子，不是终端热加载外部插件。

## 改什么动哪里

| 你想… | 动 |
| :--- | :--- |
| 换买卖组合（仍用现有叶子） | `config.py` 的 `RECIPE_*`，或网格 JSON |
| 新增叶子 | `factors/lib/<id>.py` 里 `_register_factor`，再写进 Recipe，deploy |
| 改阈值（追高、止损、均线） | `config.py`（面板已暴露的走 `panel.xml` + `PANEL_BINDS`） |
| 加仓门槛 / 本轮只加一次 | `strategy.py` `_scale_gate`，不要写进 Recipe |
| 冲突优先级 | `factors/intent.py` |
| pending 何时撤买单 | `factors/slots.py` `_pending_gate_hit`（只动 not 列表语义） |
| 下单 / T+1 / 暖机 | `scripts/qmt_common/`，然后**全策略** re-deploy |
| 交易语义说明 | [model.md](../model.md) |

新增因子成功标准：不改 `_handle` 主流程，只加 lib 文件 + Recipe 引用 + deploy。

## 常见误读

- **「gate 就是入场专用」**：`kind="gate"` 只影响入场 `real` 过滤；加仓式也可以 `not vol_dry`。
- **「出场也是一棵 and/or」**：现网 `RECIPE_EXITS` 是有序列表，按笔取第一个真叶子。
- **「pending 要信号还在才成交」**：闸门坏了才撤；信号叶子可以已灭。
- **「加仓 pending 也看 chase」**：默认 `RECIPE_SCALE_IN` 没有 `not chase`；破平台 / 金叉不受 5% 涨幅禁开。
- **「周空 Recipe 为真就全平」**：全平走 streak 确认，不是叶子当天为真。
