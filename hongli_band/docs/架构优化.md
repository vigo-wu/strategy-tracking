| 发送委托 | pending / passorder（`qmt_common`） |

## 2. 完善后的分层（草图 + 契约）

```text
                    ┌─────────┐              ┌─────────┐
                    │  OHLCV  │              │  STATE  │
                    └────┬────┘              └────┬────┘
                         └──────────┬─────────────┘
                                    ▼
                 ┌───────────────┐
                 │  Feature/Ctx  │  均线/MACD/量 + 持仓快照（算一次）
                 └───────┬───────┘
                         ▼
                 ┌───────────────┐
                 │  Factor Lib   │  中性原子：eval(ctx)→bool(+detail)
                 └───────┬───────┘
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼              ▼
     ┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐
     │  入场  │    │  出场  │    │  加仓  │    │  减仓  │
     │ Recipe │    │ Recipe │    │ Recipe │    │ Recipe │
     │ 布尔式 │    │ 布尔式 │    │ 布尔式 │    │ 布尔式 │
     └───┬────┘    └───┬────┘    └───┬────┘    └───┬────┘
         │ hit/reasons │            │              │
         └─────────────┴──────┬─────┴──────────────┘
                              ▼
                    ┌─────────────────┐
                    │    仓位管理      │  仲裁 + 目标仓/笔数/预算
                    │  (intent 合成)  │  book / lots / T+1 约束
                    └────────┬────────┘
                             ▼
                    ┌─────────────────┐
                    │   发送委托       │  pending / passorder
                    └─────────────────┘
```

相对草图补了三块实现时必需的契约：

1. **Feature/Ctx**：OHLCV **与状态**先合成 `ctx`，避免四槽各算一遍均线、各抠一遍 `A.*`。
2. **Recipe**：四槽不是写死模块，而是布尔表达式容器，从 Factor Lib **引用**原子。
3. **STATE 回写**：峰值、持仓日、因子私有计数由仓位/运行时维护；因子 `eval` 默认只读。

## 3. 核心原则

### 3.1 因子无立场

因子是构成入场/出场等结构的**最小单元**，本身不决定买/卖/加/减。

- 接口：`id` / `params` / `need` / `eval(ctx) -> (bool, detail)`
- `ctx` = **行情 + 状态 + 时钟**（见 §3.6），不是只吃 OHLCV
- 同一原子可出现在多个槽（例如 `pullback_vol` 既可进入场也可进加仓）
- **不是因子**：`BOOK_LOT_MAX`、现金不足、`scale_once`、pending 超时——属仓位/执行层

现网第一期叶子用**复合原子**（与现 reason 码对齐），不拆 `near_ma & vol_shrink`。清单见 [Recipe分类.md](./Recipe分类.md) §第一期复合原子。

### 3.2 策略结构 = 四个布尔槽

| 槽 | 典型形态 | 语义 |
| :--- | :--- | :--- |
| 入场 | `A \| B \| (C & D)` | 是否开仓 |
| 出场 | `A & (B \| C)` | 是否清仓 / 清指定笔（→0） |
| 加仓 | `A \| B \| (C & D)` | 已有仓是否再加 |
| 减仓 | `A & (B \| C)` | 是否减到更小仓（非清零） |

形态是**约定示例**，引擎应支持任意 `and` / `or` / `not` 嵌套；不要把「入场必须 OR、出场必须 AND」写死进引擎。

闸门不必单独成层：写成 `¬chase & …`（AST 里 `["not","chase"]`）即可。

### 3.3 每槽统一输出

```text
SlotResult = {
  hit: bool,
  reasons: [命中叶子因子 id…],
  detail: {...}   # 可选，日志/归因
}
```

### 3.4 仓位管理做仲裁，不写指标

四槽同日可能同时为真，默认优先级：

```text
出场 > 减仓 > 加仓 > 入场
```

硬约束（不算因子）仍在本层：

- 全池笔数 / 单票 `scale_once` / 预算与 `book_frac`
- T+1 可卖、当日加仓后是否评卖
- 执行日「有卖点则取消加仓」

输出 **Intent**（示例）：

```text
{ side, target: flat|reduce|add|open,
  lot_ids?, frac_or_shares?, reasons[] }
```

### 3.5 发送委托只消费 Intent

保持 `qmt_common` 的 pending / 成交 / T+1 / broker。  
**禁止**因子或 Recipe 直接下单。

### 3.6 因子入参：OHLCV + 状态

```text
ctx = {
  market,   # OHLCV + 已算特征（均线、MACD、量均…）
  state,    # 持仓 / 笔 / 因子可读持久态
  clock,    # 信号日、回测否、confirm vs exec（只读）
}
```

| 块 | 给因子 | 不给因子 |
| :--- | :--- | :--- |
| **market** | 日/周序列、共享特征 | 券商委托 |
| **state** | 成本、峰值、持仓日、lots、周空 streak、武装标记 | 现金、全池槽位、pending 超时 |
| **clock** | `sig_day`、是否累计 streak | 下单窗、心跳 |

`eval` **默认只读** `ctx`。持仓派生态（峰值、持仓日、除权缩放）在进因子前由运行时更新。因子私有计数（如 `_w_bear_streak`）在 spec 声明 `state_keys`，由引擎/仓位层在 bar 结束写回，勿在 `eval` 里直接改 `A.*`（同一叶子进多槽会算乱）。

粒度：入场/闸门用票级 `state.position`；出场/减仓按 lot 填 `state.lot` 再 `eval`（对齐现 `_eval_lot_sell`）。不要把整本 book 塞进因子。

## 4. Recipe = 参数组真源

一份可回测、可网格扫描的配置：

```text
Recipe = {
  entry:     布尔式,
  exit:      布尔式,
  scale_in:  布尔式,
  scale_out: 布尔式,          # 可先恒 false
  factor_params: { ... },     # 各原子参数
  structure: { ... },         # D_MA_* / MACD_* 等共享特征输入
  sizing:    { ... },         # BOOK_LOT_MAX / LOT_* / 减仓比例
  priority:  ["exit","scale_out","scale_in","entry"]  # 可选覆写
}
```

「动态增删因子、自由组合定参数组」= 改 Recipe + 使用已注册原子，而不是改 `_handle` 分支。

布尔式 AST（便于 JSON / 网格）见 [Recipe分类.md](./Recipe分类.md)。

## 5. 对照当前 HlBand

| 草图层 | 今天实际 | 差距 |
| :--- | :--- | :--- |
| Feature/Ctx | `indicators` + `_handle` 内临时算；状态散在 `A.*` / lots | 未统一 `ctx.market` + `ctx.state` |
| Factor Lib | 散落在 `_eval_daily_buy` / trail / weekly guard… | 未注册、未中性拆分 |
| 入场 Recipe | `¬gates & pullback_vol`（写死） | 无表达式 |
| 出场 Recipe | stop→trail→time_force 链 + weekly_bear | 近似多规则，非一棵式 |
| 加仓 Recipe | 门槛 & `(pb \| plat \| macd)` | 最接近；门槛宜留仓位层 |
| 减仓 Recipe | 基本没有 | 草图有、代码缺 |
| 仓位管理 | `budget.py` + lots + book | 有实现，但与信号缠在 `_handle` |
| 发送委托 | `qmt_common` orders/pending | 已分离，保持 |

用记号重写现状（迁移时默认 Recipe 应对齐此行为）：

```text
入场 ≈ ¬chase & ¬vol_dry & ¬w_bias & ¬w_slope & ¬weekly_bear & pullback_vol
加仓 ≈ 仓位门槛 & (pullback_vol | plat_break | w_macd_golden)
出场 ≈ 有序规则：stop_loss → trail_stop → time_force；另 weekly_bear 确认清仓
减仓 ≈ （空）
```

说明：

- 出场今天是**优先级链**，不完全等于单棵 `A & (B|C)`。统一布尔槽后，要么多条命名出场式按列表优先级，要么一棵式为真后用命中叶子的稳定排序选 `reason`。
- `D_MA_MID=0` 这类「关周期」是弱开关，长期应拆成：结构参数 + 表达式是否引用依赖该结构的因子。

## 6. 与网格 / local_bt

- 格子从「拍平 config 常量 overrides」升级为「Recipe 差分」（改某槽子树或某因子参数）。
- 探针指纹带上 `recipe_hash` + 关键参数。
- **两层扫参**：
  - 组合轴：少数命名布尔变体（例如「入场只要回踩」「入场=回踩|破平台」）
  - 数值轴：式子锁定后再扫阈值
- 禁止对所有因子做 `2^n` 开关笛卡尔积；仍遵守命名少格 + 样本外门（见 `qmt-local-bt-grid`）。

QMT 约束：片段禁止互相 `import`，靠 `MODULE_ORDER` 拼接。  
「动态」= **部署/回测期按 Recipe 选用已编进包的因子**，不是终端热加载外部插件。

## 7. 落地顺序

1. **抽出 Factor Lib + `hit(expr)` + 只读 `ctx`(行情+状态)**，四槽先写成与今天等价的默认 Recipe（复合原子）；减仓可恒 `false`。
2. **仓位管理收口仲裁**（出场优先于加仓等），委托层不动。
3. **config / 网格认 Recipe**；结构参数与因子参数分栏。
4. **再实现减仓槽**（新动作：按比例/按笔减，勿与「全平出场」混用）。
5. 新因子 = 只加库 + 改 Recipe，不改主干。

成功标准：

- 新增进场因子：不改 `_handle` 主流程，只加因子 + Recipe 启用。
- 一组参数组 = 一份 Recipe（+ overrides），探针能打出 `recipe=` 指纹。
- 默认 Recipe 回放与重构前成交对齐（回归）。

---

## 8. 图例一句话

> Factor Lib 吃行情+状态快照，产出中性布尔；入场/出场/加仓/减仓各持一棵 Recipe；仓位管理仲裁、sizing 并写回状态；发送委托只消费 Intent。
