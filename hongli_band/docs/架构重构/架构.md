# HlBand 目标架构

本文是重构分层的真源。总图：[策略架构.drawio](./策略架构.drawio)。

因子中性与布尔 AST 仍见 [Recipe分类.md](Recipe分类.md)；旧稿 [架构优化.md](../架构优化.md) 只保留契约细节，以本文为准。

目标：行情与复权分流 → 指标算一次 → 中性因子 → 四槽 Recipe → 仓位仲裁出 Intent → `qmt_common` 下单。执行层不改。

---

## 1. 总链

```text
                    ┌──────────────────────────────────────────┐
                    │  Runtime / 时钟                            │
                    │  QMT handlebar · local_bt · confirm/exec   │
                    └────────────────────┬─────────────────────┘
                                         ▼
     ┌─────────┐              ┌──────────────────┐
     │  OHLCV  │              │  STATE           │
     │ 1d / 1w │              │ 票态 + 全池账本    │
     └────┬────┘              └────────┬─────────┘
          │                            │
          ├─回测──► 动态复权(PIT) ──┐   │
          │                        │   │
          └─实盘──► QMT front* ────┼───┤
                                   ▼   │
                            技术指标库   │   只吃复权序列
                            MA/EMA/MACD │
                                   ▼   │
                            Feature/Ctx ◄┘   market + 持仓快照 + clock
                                   ▼
                              因子库（中性）
                         eval(ctx) → bool + detail
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
              入场侧 Recipe                  出场侧 Recipe
           开仓          加仓            清仓          减仓
                    └──────────────┬──────────────┘
                                   ▼
                            仓位管理
                     仲裁 · book 分档 · T+1 · sizing
                                   ▼
                              Intent
                                   ▼
                            发送委托
                      pending / passorder（qmt_common）
                                   ▼
                            STATE 回写
```

相对旧草图改了四处：

1. **实盘是旁路**，不是绕回 OHLCV 的反馈环。回测走 PIT；实盘用 QMT `front*`，跳过动态复权。
2. **两套复权分开**：行情 PIT 只服务回测 OHLCV；持仓除权（`cost` / `hold_peak` / 股数）挂在 STATE 更新。
3. **技术指标库不吃 STATE**。持仓进因子与仓位；现金、账本、pending 只进仓位层。
4. **入场/出场是两侧，内部四槽**。开仓 ≠ 加仓，清仓 ≠ 减仓。

## 2. 各层契约

### 2.1 Runtime / 时钟

不参与信号计算，只决定算哪根 K、能不能下单。

| 模式 | 信号用的 K | 成交 |
| :--- | :--- | :--- |
| 回测 | 当根已收盘日/周 | 收盘价；T+1 残留次日开盘 |
| 实盘 confirm（约 14:56） | 当日完整日 K；周线丢掉未收盘周 | 不报单，只写 pending + 打卡 |
| 实盘 exec（14:56:40–14:57） | 不评新信号 | 卖一/买一限价 |
| 开盘兜底 | 上一完整交易日 | 开盘价市价 |

`weekly_bear` 的 streak 只在 confirm / 回测 / 开盘兜底累计，盘中 exec 只读。这是 clock，不是因子。

对应：`runtime.py`、`universe.py` 的 `_compute_live_work`、`strategy.py` 里 confirm/exec 切片。

---

### 2.2 OHLCV → 动态复权

输入：日/周 OHLCV（`market.py`）。

- 回测：`_maybe_pit_ohlcv` → `common:pit_front`（`front_ratio` 用 `Πdr`，`front` 用价差事件序）。
- 实盘：`_api_dividend_type` 走 QMT `front*`。
- 成交量不复权。

下游只认**同一套逻辑前复权价**，指标库不感知 PIT 还是券商复权。

持仓除权是另一条路：`common:single/ex_rights` 在评卖前缩放该票 `cost` / `hold_peak` / 股数。实盘与 PIT 回测都做；静态 front* CSV 回测跳过。

---

### 2.3 技术指标库

只做序列变换，算一次，写入 `ctx.market`。无立场、无持仓。

落地文件导航：[indicators/NAV.md](../../scripts/qmt/hlband/indicators/NAV.md)。

**单独建目录，按指标名一文件一个。** 禁止再把 SMA/EMA/MACD 写进同一个 `indicators.py`。现有单文件拆掉，避免和目录重名。

```text
hlband/indicators/
  sma.py          # _sma
  ema.py          # _ema
  macd.py         # _calc_macd（只用已拼入的 _ema）
  atr.py          # 草图有、现网未用；需要再加
  util.py         # _last_valid / _cross_up / _cross_down（不是指标）
  price_ma.py     # 可选：按标的选 SMA/EMA，读 BOOK_STOCKS.ma_type
```

| 文件 | 算指标 | 说明 |
| :--- | :--- | :--- |
| `sma` / `ema` / `macd` / `atr` | 是 | 只吃序列，产出序列 |
| `util.py` | 否 | 金叉、取末值，给 MACD/因子用 |
| `price_ma.py` / `_ma_kind` | 否 | 读池配置，不是指标算法 |
| `_near_ma` / `_plat_window` | 否 | 因子辅助，进 `factors/lib` |

不算指标：`chase`、`pullback_vol`、`trail_stop`。那是因子，不要放进本目录。

片段禁止互 `import`。`macd.py` 直接调用 `_ema`，靠 `MODULE_ORDER` 保证先拼 `ema.py`。指标文件不读 `A.lots` / 现金 / pending。

纯算法（sma/ema/macd/atr/util）以后可原样迁到 `scripts/qmt_common/indicators/`，路径改 `common:indicators/sma.py`，全策略 re-deploy。`price_ma` 仍留策略侧。

`_eval_weekly` 里算 MA/MACD 是指标，判空头/金叉是因子——重构时拆开。

### 2.4 Feature / Ctx

四槽不要各算一遍均线、各抠一遍 `A.*`。

```text
ctx = {
  market:  复权 OHLCV + 已算均线/MACD/量均,
  state:   该票持仓 / 当前 lot / 因子可读计数（如 w_bear_streak）,
  clock:   sig_day、confirm vs exec、是否回测,
}
```

| 给因子 | 不给因子 |
| :--- | :--- |
| 成本、峰值、持仓日、lots、周空 streak | 现金、全池槽位、pending 超时 |
| `sig_day`、是否累计 streak | 下单窗、心跳 |

`eval` 只读。峰值、持仓日、除权缩放在进因子前由运行时更新；`_w_bear_streak` 在 bar 结束由引擎写回，不要在 `eval` 里改 `A.*`。

入场/闸门用票级 `state.position`；出场/减仓按 lot 填 `state.lot` 再 `eval`（对齐 `_eval_lot_sell`）。

---

### 2.5 因子库

接口：`id` / `params` / `need` / `eval(ctx) → (bool, detail)`。

因子不决定买/卖/加/减；立场由所在槽的表达式赋予。同一原子可进多槽（例如 `pullback_vol` 进开仓和加仓）。

落地文件导航：[factors/NAV.md](../../scripts/qmt/hlband/factors/NAV.md)、[factors/lib/NAV.md](../../scripts/qmt/hlband/factors/lib/NAV.md)。

**引擎与叶子分开：根目录是引擎，`lib/` 里按因子 id 一文件一个。** 禁止把多个原子写进同一个文件，也禁止把因子塞进 `indicators/`。

```text
hlband/factors/
  ctx.py              # Feature/Ctx 组装（只读快照）
  registry.py         # 注册表：id → eval
  expr.py             # hit(and/or/not)
  slots.py            # 四槽 Recipe → SlotResult
  intent.py           # 仓位仲裁壳 → Intent（规则仍可读 budget）
  lib/                # 中性原子，文件名 = 因子 id
    pullback_vol.py
    chase.py
    vol_dry.py
    w_bias.py
    w_slope.py
    weekly_bear.py
    plat_break.py
    w_macd_golden.py
    stop_loss.py
    trail_stop.py
    time_force.py
```

| 路径 | 是因子叶子 | 说明 |
| :--- | :--- | :--- |
| `lib/<id>.py` | 是 | 一个 id 一个文件；`eval(ctx)` 只读 |
| `ctx` / `registry` / `expr` / `slots` | 否 | 引擎；不写买卖语义 |
| `intent.py` | 否 | 仲裁输出 Intent，属仓位层胶水 |
| `indicators/*` | 否 | 序列变换，不是因子 |

第一期用复合原子，与现 reason 码对齐，不拆 `near_ma & vol_shrink`：

| id | 文件 | 现逻辑 |
| :--- | :--- | :--- |
| `pullback_vol` | `lib/pullback_vol.py` | 贴 MA20/60 + 连续缩量 |
| `chase` / `vol_dry` | `lib/chase.py` / `lib/vol_dry.py` | 追高 / 无量阴跌 |
| `w_bias` / `w_slope` / `weekly_bear` | 同名 `lib/*.py` | 周线闸门 |
| `plat_break` / `w_macd_golden` | 同名 `lib/*.py` | 加仓触发 |
| `stop_loss` / `trail_stop` / `time_force` | 同名 `lib/*.py` | 按笔出场 |

新因子 = 在 `lib/` 加文件 + `registry` 登记 + Recipe 引用，不改 `_handle`。

不是因子、不要进 `lib/`：`BOOK_LOT_MAX`、现金不足、`scale_once`、`SCALE_ARM`、pending 超时、T+1。留在仓位层。`_near_ma` / `_plat_window` 作为某叶子的内部辅助，写在对应 `lib/<id>.py` 里，不单独成因子。

片段禁止互 `import`。`MODULE_ORDER` 先拼 `ctx` → 各 `lib/<id>.py` → `registry` → `expr` → `slots`（`registry` 须能看到叶子符号）。叶子不读现金 / 账本 / pending，不调用 `passorder`。

引擎（`expr` / `registry` / `slots`）以后可迁 `scripts/qmt_common/factors/`；**叶子留在策略侧**，不要把 HlBand 语义焊进所有策略。

### 2.6 入场 / 出场 = 两侧四槽

图上保留买侧/卖侧；实现各持两棵 Recipe。形态是示例，引擎支持任意 `and` / `or` / `not`。闸门写成 `["not","chase"]`，不单独成层。

现网默认（迁移第一期对齐行为，不先改语义）：

```text
入场侧
  entry:     ¬chase & ¬vol_dry & ¬w_bias & ¬w_slope & ¬weekly_bear & pullback_vol
  scale_in:  （门槛在仓位层）pullback_vol | plat_break | w_macd_golden

出场侧
  exit:      有序：weekly_bear(确认) > stop_loss > trail_stop > time_force
  scale_out: false   # 减仓未启用；Intent 预留 reduce，strategy 忽略
```

每槽输出：`{ hit, reasons[], detail }`。

出场今天是优先级链，不是单棵 `A & (B|C)`。第一期用「多条命名出场式 + 稳定排序选 reason」。

AST 与叶子清单见 [Recipe分类.md](Recipe分类.md)。

---

### 2.7 仓位管理

四槽同日可为真，默认：

```text
清仓 > 减仓 > 加仓 > 开仓
```

硬约束（不算因子）：

- 全池 `BOOK_LOT_MAX`、50%/30%/剩余、`book_frac`
- `scale_once`、大仓空时开仓优先于加仓
- T+1 可卖、加仓当日 `skip_sell_eval_day`
- 执行日有卖点则取消加仓

STATE 拆开：

| 块 | 存哪 | 谁读 |
| :--- | :--- | :--- |
| 持仓数据 | `STATE_FILE`（按 `{stock}` 分文件）+ `A.lots` | 因子 + 仓位 |
| 账户/账本 | `BOOK_FILE`（全池一份）+ 券商资金 | 仅仓位管理 |

禁止多实例共写同一 `BOOK_FILE` / 同一 `STATE_FILE`。

输出 Intent：

```text
{ side, target: open|add|flat|reduce, lot_ids?, frac?, reasons[] }
```

---

### 2.8 发送委托

只消费 Intent。保持 `qmt_common`：`orders_pending`、`single/orders`、T+1、成交回调。

因子 / Recipe 禁止 `passorder`。

HlBand 特有：成交后才清 pending、部分成交保留 `lot_ids`——继续用 `_pending_on_*`，不要把 pending 状态机搬进因子。

委托成交后回写持仓 STATE 与全池账本，形成闭环。这是该画的回边，不是「实盘绕回 OHLCV」。

## 3. 与现网对照

| 目标层 | 今天实际 | 差距 |
| :--- | :--- | :--- |
| Runtime / 时钟 | `runtime.py` + `universe.py` + `_handle_stock` 前半 | 已有，和信号缠在一起 |
| 动态复权 | `market._maybe_pit_ohlcv` + `common:pit_front` | 层在，须画成旁路 |
| 持仓除权 | `common:single/ex_rights`，评卖前调用 | 别并进动态复权 |
| 技术指标库 | 单文件 `indicators.py`；周线/日线特征仍在 `strategy.py` | 未拆成 `indicators/<名>.py`，也未一次组装 |
| 因子库 | `_eval_daily_buy` / `_eval_lot_sell` / trail / weekly… 仍在 `strategy.py` | 未落到 `factors/lib/<id>.py`，未注册、未中性 |
| 四槽 Recipe | 入场/加仓写死；出场是 if 链；减仓无 | 无表达式 |
| 仓位管理 | `budget.py` + lots + `_scale_gate` | 有实现，和 `_handle` 缠在一起 |
| 发送委托 | `qmt_common` orders/pending | 已分离，保持 |

`_handle_stock` 仍是「取数 → 算指标 → 判买卖 → 打卡 → 执行 pending → 挂新 pending」一条龙。目标拆成：**组 ctx → 评四槽 → 仓位合成 Intent → 委托**。

## 4. 两套 Runtime，一套内核

```text
          ┌─ QMT 终端（GBK 拼接包）
内核 ────┤
          └─ local_bt（同一套函数 + CSV/mock）
```

网格 / 稳健门扫 **Recipe 差分**（改某槽子树或某因子阈值），不做全因子 `2^n` 开关。组合轴少、数值轴后扫，见 `qmt-local-bt-grid`。

QMT：片段不能互相 `import`，靠 `MODULE_ORDER` 拼接。「动态加因子」= 部署期把已注册原子编进包，不是终端热加载。

目标拼接（在现有单仓模板上插指标目录 + 因子，不改 common 买卖层）：

```text
config → …
→ indicators/util.py → indicators/sma.py → indicators/ema.py
→ indicators/macd.py → indicators/atr.py → indicators/price_ma.py
→ common:market_util.py → common:pit_front.py → market.py
→ factors/ctx.py
→ factors/lib/pullback_vol.py → factors/lib/chase.py → factors/lib/vol_dry.py
→ factors/lib/w_bias.py → factors/lib/w_slope.py → factors/lib/weekly_bear.py
→ factors/lib/plat_break.py → factors/lib/w_macd_golden.py
→ factors/lib/stop_loss.py → factors/lib/trail_stop.py → factors/lib/time_force.py
→ factors/registry.py → factors/expr.py → factors/slots.py → factors/intent.py
→ mode → broker → orders
→ budget → strategy(只剩仲裁+挂 pending) → universe → runtime
```

## 5. 落地顺序

1. 拆 `indicators.py` 为 `indicators/<指标名>.py`（一指标一文件）+ 只读 ctx，`_handle` 先只改组装方式，成交对齐。
2. 按 `factors/lib/<id>.py` 拆复合原子 + `registry` / `hit(expr)`，默认 Recipe 对齐现网；减仓恒 `false`。新叶子只加 `lib/` 文件。
3. 仓位管理收口仲裁（出场优先于加仓），委托层不动。
4. config / 网格认 Recipe；结构参数与因子参数分栏。
5. 需要时再做减仓槽（按比例/按笔，勿和全平混用）。

成功标准：

- 新进场因子：只加库 + Recipe 启用，不改 `_handle` 主流程
- 默认 Recipe 回放与重构前成交对齐
- 探针能打出 `recipe=` 指纹
