# FactorBand 目标架构

本文是重构分层的唯一可信数据源。总图：[策略架构.drawio](./策略架构.drawio)。

因子中性与布尔 AST 仍见 [Recipe分类.md](Recipe分类.md)；旧稿 [架构优化.md](../架构优化.md) 只保留契约细节，以本文为准。

目标：行情与复权分流 → 指标算一次 → 中性因子 → 买入 `entry`、加仓 `scale_in`、卖出 `exit`、减仓 `scale_out` 四个槽位的 Recipe → 仓位仲裁出 Intent → `qmt_common` 下单。执行层不改。

---

## 1. 总链

```text
                    ┌──────────────────────────────────────────┐
                    │  Runtime / 时钟                            │
                    │  QMT handlebar · local_bt · confirm/exec   │
                    └────────────────────┬─────────────────────┘
                                         ▼
     ┌─────────┐              ┌──────────────────┐
     │  OHLCV  │              │  STATE           │
     │ 1d / 1w │              │ 票态 + 全池账本    │
     └────┬────┘              └────────┬─────────┘
          │                            │
          ├─回测──► 动态复权(PIT) ──┐   │
          │                        │   │
          └─实盘──► QMT front* ────┼───┤
                                   ▼   │
                            技术指标库   │   仅接受复权行情序列作为输入
                            MA/EMA/ATR  │
                                   ▼   │
                            Feature/Ctx ◄┘   market + 持仓快照 + clock
                                   ▼
                              因子库（中性）
                         eval(ctx) → bool + detail
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
              入场侧 Recipe                  出场侧 Recipe
           开仓          加仓            清仓          减仓
                    └──────────────┬──────────────┘
                                   ▼
                            仓位管理
                     仲裁 · book 分档 · T+1 · sizing
                                   ▼
                              Intent
                                   ▼
                            发送委托
                      pending / passorder（qmt_common）
                                   ▼
                            STATE 回写
```

相对旧草图改了四处：

1. **实盘是旁路**，不是绕回 OHLCV 的反馈环。回测走 PIT；实盘用 QMT `front*`，跳过动态复权。
2. **两套复权分开**：行情 PIT 只服务回测 OHLCV；持仓除权（`cost` / `hold_peak` / 股数）挂在 STATE 更新。
3. **技术指标库不读取 STATE**。持仓进因子与仓位；现金、账本、pending 只进仓位层。
4. **入场/出场是两侧，内部四个槽位**。开仓 ≠ 加仓，清仓 ≠ 减仓。

## 2. 各层契约

### 2.1 Runtime / 时钟

不参与信号计算，只决定算哪根 K、能不能下单。

| 模式 | 信号用的 K | 成交 |
| :--- | :--- | :--- |
| 回测 | 当根已收盘日/周 | 收盘价；T+1 残留次日开盘 |
| 实盘 confirm（约 14:56） | 当日完整日 K；周线丢掉未收盘周 | 不报单，只写 pending + 打卡 |
| 实盘 exec（14:56:40–14:57） | 不评新信号 | 卖一/买一限价 |
| 开盘兜底 | 上一完整交易日 | 开盘价市价 |

对应：`runtime.py`、`universe.py` 的 `_compute_live_work`、`strategy.py` 里 confirm/exec 切片。

---

### 2.2 OHLCV → 动态复权

输入：日/周 OHLCV（`market.py`）。四个槽位未引用周线叶子时 `_ohlcv_need_1w()` 为 0，预取与策略路径不拉 1w；`_get_ohlcv_1w` 直接调用仍按 `RECIPE.structure` 指标周期窗取数。

- 回测：`_maybe_pit_ohlcv` → `common:pit_front`（`front_ratio` 用 `Πdr`，`front` 用价差事件序）。

- 回测：`_maybe_pit_ohlcv` → `common:pit_front`（`front_ratio` 用 `Πdr`，`front` 用价差事件序）。
- 实盘：`_api_dividend_type` 走 QMT `front*`。
- 成交量不复权。

下游只认**同一套逻辑前复权价**，指标库不感知 PIT 还是券商复权。

持仓除权是另一条路：`common:single/ex_rights` 在评卖前缩放该票 `cost` / `hold_peak` / 股数。实盘与 PIT 回测都做；静态 front* CSV 回测跳过。

### 2.3 技术指标库

只做序列变换，由 `ctx` 按启用叶子调用后写入 `ctx.market`。无立场、无持仓。指标函数本身不读 `RECIPE`。

落地文件导航：[indicators/NAV.md](../../scripts/qmt/fband/indicators/NAV.md)。

**单独建目录，按指标名一文件一个。** 禁止再把 SMA/EMA/ATR 写进同一个 `indicators.py`。现有单文件拆掉，避免和目录重名。

```text
hlband/indicators/
  sma.py          # _sma
  ema.py          # _ema
  atr.py          # _calc_atr（威尔德平滑；n 必传）
  keltner.py      # _calc_keltner（_ma ± k×ATR；ma_n / atr_n / k / kind 必传）
  util.py         # _last_valid / _cross_up / _cross_down（不是指标）
```

| 文件 | 算指标 | 说明 |
| :--- | :--- | :--- |
| `sma` / `ema` / `atr` / `keltner` | 是 | 仅接受行情序列作为输入，产出序列 |
| `util.py` | 否 | 金叉、取末值，给因子用 |

不算指标：`keltner_vol`、`trail_stop`。那是因子，不要放进本目录。

片段禁止互 `import`。`keltner.py` 调用 `_ma` / `_calc_atr`，须在 ma / atr 之后。指标文件不读 `A.lots` / 现金 / pending，也不读 `RECIPE`：`_calc_atr` 的 `n` 必传，`_calc_keltner` 的 `ma_n` / `atr_n` / `k` / `kind` 必传，`_ma(closes, n, kind)` 由调用方传入算法。价格均线缺键为 0。`above_ma` 周期在 `RECIPE.factor_params`（`above_ma.n`），由 ctx 传入 `_ma`，不读 `structure.ma.1d.trend`。其余窗与 `ma.kind` 由 `factors/ctx._structure_windows()` 从 `RECIPE.structure`（`ma.<period>.<window>`，周期键对齐 `_VALID_PERIODS`）取出再传入。倍数 `k` 由调用方传入，不上 `structure`。旧 `structure.ema` / `sma` / `macd` 段写入即报错。

纯算法（sma/ema/atr/keltner/util）以后可原样迁到 `scripts/qmt_common/indicators/`，路径改 `common:indicators/sma.py`，全策略 re-deploy。

周线 MA 在 `factors/ctx._weekly_market_features` 预计算（`ma.1w.mid` / `slow` / `trend` 缺键为 0）。默认盘无叶子需要 `weekly` 时 `_ohlcv_need_1w()` 为 0。

### 2.4 Feature / Ctx

四个槽位不要各算一遍均线、各抠一遍 `A.*`。

```text
ctx = {
  market:  复权 OHLCV + 启用叶子所需的均线/ATR/肯特纳/量均,
  state:   该票持仓 / 当前 lot,
  clock:   sig_day、confirm vs exec、是否回测,
}
```

`LEAVES.need` 把叶子 id 映射到预计算标签；`_market_need()` 扫四个槽位（`scale_in` 非空仍要 `scale_arm`）。未知 AST id 按全标签算。缺 `need` 或非法标签在 ctx 组表时报错。`daily_ready` = 日线 `closes` 存在且 `i>=2`，不绑未引用的量均。未算字段键仍在、值为 `None`。行情键是角色名（`d_mid` / `d_slow` / `d_trend`、周线 `w_mid` / `w_trend`），不是历史窗号。

| 给因子 | 不给因子 |
| :--- | :--- |
| 成本、峰值、持仓日、lots | 现金、全池槽位、pending 超时 |
| `sig_day` | 下单窗、心跳 |

`eval` 只读。峰值、持仓日、除权缩放在进因子前由运行时更新，不要在 `eval` 里改 `A.*`。

入场/闸门用票级 `state.position`；出场/减仓按 lot 填 `state.lot` 再 `eval`（对齐 `_eval_lot_sell`）。

### 2.5 因子库

接口：`id` / `params` / `need` / `eval(ctx) → (bool, detail)`。`need` 写在 [catalog.py](../../scripts/qmt/fband/factors/catalog.py) 的 `LEAVES`（预计算标签），不是网格轴字段；[ctx.py](../../scripts/qmt/fband/factors/ctx.py) 组表时校验并按启用叶子闸预计算。

因子不决定买/卖/加/减；立场由所在槽的表达式赋予。同一原子可进多槽（例如 `keltner_vol` 进开仓和加仓）。

落地文件导航：[factors/NAV.md](../../scripts/qmt/fband/factors/NAV.md)、[factors/lib/NAV.md](../../scripts/qmt/fband/factors/lib/NAV.md)。

**引擎与叶子分开：根目录是引擎，`lib/` 里按因子 id 一文件一个。** 禁止把多个原子写进同一个文件，也禁止把因子塞进 `indicators/`。

```text
hlband/factors/
  catalog.py          # LEAVES：登记 / need / 默认阈值 / 网格轴；写入 RECIPE.factor_params
  ctx.py              # Feature/Ctx 组装（只读快照）
  registry.py         # 按 LEAVES 取 id → eval
  expr.py             # hit(and/or/not)
  slots.py            # 四个槽位 Recipe → SlotResult
  intent.py           # 仓位仲裁壳 → Intent（规则仍可读 budget）
  lib/                # 中性原子，文件名 = 因子 id
    keltner_vol.py
    above_ma.py
    scale_arm.py
    stop_loss.py
    atr_stop.py
    trail_stop.py
    atr_trail_stop.py
    time_force.py
```

| 路径 | 是因子叶子 | 说明 |
| :--- | :--- | :--- |
| `lib/<id>.py` | 是 | 一个 id 一个文件；`eval(ctx)` 只读 |
| `ctx` / `registry` / `expr` / `slots` | 否 | 引擎；不写买卖语义 |
| `intent.py` | 否 | 仲裁输出 Intent，属仓位层胶水 |
| `indicators/*` | 否 | 序列变换，不是因子 |

第一期用复合原子，与现 reason 码对齐，不拆 `keltner_inside & vol_shrink`：

| id | 文件 | 现逻辑 |
| :--- | :--- | :--- |
| `keltner_vol` / `above_ma` | `lib/keltner_vol.py` / `lib/above_ma.py` | 通道内缩量 / 价在趋势均线上 |
| `scale_arm` | `lib/scale_arm.py` | 加仓门槛：浮盈/持仓日（默认 `scale_in` 未启用） |
| `stop_loss` / `atr_stop` / `trail_stop` / `atr_trail_stop` / `time_force` | 同名 `lib/*.py` | 按笔出场 |

新因子 = `catalog.LEAVES` + `lib/<id>.py` + 必要时改四个槽位的条件抽象语法树，不改 `_handle`，不手改 `registry` / `MODULE_ORDER` / `grid_spec` 白名单。运行时阈值是 `RECIPE.factor_params`（catalog 写入），叶子用 `_factor_param(ctx, id, key)` 读，**不要**再加 `STOP_LOSS` 这类模块全局。

不是因子、不要进 `lib/`：`BOOK_LOT_MAX`、现金不足、`scale_once`、pending 超时、T+1。留在仓位层。`SCALE_ARM` / `SCALE_ARM_BARS` / `SCALE_W_HIST_MIN` 已删，顶层写入即报错。

片段禁止互 `import`。`MODULE_ORDER` 先拼 `config` → `catalog` → `ctx` → 各 `lib/<id>.py`（顺序跟 `LEAVES`）→ `registry` → `expr` → `slots`（`registry` 须能看到叶子符号）。叶子不读现金 / 账本 / pending，不调用 `passorder`。

引擎（`expr` / `registry` / `slots`）以后可迁 `scripts/qmt_common/factors/`；**叶子留在策略侧**，不要把 HlBand 语义焊进所有策略。

### 2.6 入场 / 出场 = 两侧四个槽位

图上保留买侧/卖侧；实现各持两棵 Recipe。形态是示例，引擎支持任意 `and` / `or` / `not`。闸门写成 `["not","leaf"]`，不单独成层。

现行默认配置：

```text
入场侧
  entry:     above_ma & keltner_vol
  scale_in:  false
             # scale_arm 仍登记；启用后由 _recipe_compute_leaves 特例拉入
             # scale_once / 满槽在仓位层

出场侧
  exit:      atr_stop | atr_trail_stop
             # stop_loss / trail_stop / time_force 叶子仍在，默认 AST 不引用
  scale_out: false   # 减仓未启用；Intent 预留 reduce，strategy 忽略
```

每槽输出：`{ hit, reasons[], detail }`。

出场是一棵 `or`（短路，主因 = 第一个命中叶子）。按笔评卖时 ctx 带 lot。

AST 与叶子清单见 [Recipe分类.md](Recipe分类.md)。

因子数字作者写在 `catalog.LEAVES`，运行时只活在已写入的 `RECIPE.factor_params`（`stop_loss.pct`、`atr_stop.k`、`atr_trail_stop.k1` / `k2`、`time_force.arm`、`trail_stop.tiers`、`scale_arm.arm` / `bars`、`keltner_vol.*`、`above_ma.n`…）。ATR/肯特纳窗与显式价格均线窗只活在 `RECIPE.structure`（价格均线缺键为 0；完整键表见 [Recipe分类.md](Recipe分类.md) §8；价格均线为 `ma.<period>.<window>`，周期键对齐 `_VALID_PERIODS`）。`above_ma` 周期是 `above_ma.n`，不是 `structure.ma.1d.trend`。`scale_once` / 资金仍是仓位层。网格轴 id 是点路径，轴元数据来自 `LEAVES`，侧栏 / `catalog_ids()` 只含买入 `entry`、加仓 `scale_in`、卖出 `exit`、减仓 `scale_out` 四个槽位已启用叶子的阈值（`stop_loss` 登记保留、默认不上轴）。格子 overrides 必须嵌套 `{"factor_params": {"stop_loss": {"pct": 0.06}}}` 或 `{"structure": {"ma": {"1d": {"mid": 15}}}}`；顶层旧键（`STOP_LOSS` / `D_MA_MID` / `SCALE_ARM`）或顶层点路径（`stop_loss.pct` / `d_ma.mid` / `ma.1d.mid`）直接报错；袋内旧段 `d_ma`/`w_ma`/`macd`/`ema`/`sma` 亦报错。面板只上模拟下单 / 资金 / 加仓开关。

### 2.7 仓位管理

四个槽位同日可为真，默认：

```text
清仓 > 减仓 > 加仓 > 开仓
```

硬约束（不算因子）：

- 全池 `BOOK_LOT_MAX`、50%/30%/剩余、`book_frac`
- `scale_once`、大仓空时开仓优先于加仓
- T+1 可卖、加仓当日 `skip_sell_eval_day`
- 执行日有卖点则取消加仓

STATE 拆开：

| 块 | 存哪 | 谁读 |
| :--- | :--- | :--- |
| 持仓数据 | `STATE_FILE`（按 `{stock}` 分文件）+ `A.lots` | 因子 + 仓位 |
| 账户/账本 | `BOOK_FILE`（全池一份）+ 券商资金 | 仅仓位管理 |

禁止多实例共写同一 `BOOK_FILE` / 同一 `STATE_FILE`。

输出 Intent：

```text
{ side, target: open|add|flat|reduce, lot_ids?, frac?, reasons[] }
```

### 2.8 发送委托

只消费 Intent。保持 `qmt_common`：`orders_pending`、`single/orders`、T+1、成交回调。

因子 / Recipe 禁止 `passorder`。

HlBand 特有：成交后才清 pending、部分成交保留 `lot_ids`——继续用 `_pending_on_*`，不要把 pending 状态机搬进因子。

委托成交后回写持仓 STATE 与全池账本，形成闭环。这是该画的回边，不是「实盘绕回 OHLCV」。

## 4. 两套 Runtime，一套内核

```text
          ┌─ QMT 终端（GBK 拼接包）
内核 ────┤
          └─ local_bt（同一套函数 + CSV/mock）
```

网格 / 稳健门扫 **Recipe 差分**（改某槽子树、某因子阈值或某 `RECIPE.structure` 指标周期窗），不做全因子 `2^n` 开关。因子/结构轴用点路径（`stop_loss.pct`、`ma.1d.mid`），覆盖写嵌套 `overrides.factor_params` / `overrides.structure`；资金仍写顶层全局名。见 `qmt-local-bt-grid`。

QMT：片段不能互相 `import`，靠 `MODULE_ORDER` 拼接。「动态加因子」= 部署期把已注册原子编进包，不是终端热加载。

目标拼接（在现有单仓模板上插指标目录 + 因子，不改 common 买卖层）：

```text
config → factors/catalog.py → …
→ indicators/util.py → indicators/sma.py → indicators/ema.py
→ indicators/atr.py
→ common:market_util.py → common:pit_front.py → market.py
→ factors/ctx.py
→ factors/lib/<id>.py（顺序 = LEAVES 插入序；缺文件/孤儿报错）
→ factors/registry.py → factors/expr.py → factors/slots.py → factors/intent.py
→ mode → broker → orders
→ budget → strategy(只剩仲裁+挂 pending) → universe → runtime
```

## 5. 落地顺序

1. 拆 `indicators.py` 为 `indicators/<指标名>.py`（一指标一文件）+ 只读 ctx，`_handle` 先只改组装方式，成交对齐。
2. 按 `factors/lib/<id>.py` 拆复合原子 + `catalog.LEAVES` / `hit(expr)`，默认 Recipe 对齐现行默认配置；减仓恒 `false`。新叶子改 `LEAVES` + `lib/<id>.py` + 可选 AST。
3. 仓位管理收口仲裁（出场优先于加仓），委托层不动。
4. 因子数字写 `catalog.LEAVES`（运行时 `RECIPE.factor_params`，含 `above_ma.n`）；ATR/肯特纳窗与显式价格均线窗只写 `RECIPE.structure`（价格均线缺键为 0）。网格认嵌套 `overrides.factor_params` / `overrides.structure`。仓位不做 sizing 分栏，阈值和指标周期窗不上屏。
5. 需要时再做减仓槽（按比例/按笔，勿和全平混用）。

成功标准：

- 新进场因子：`catalog` + `lib/<id>.py` + Recipe 启用，不改 `_handle` 主流程
- 默认 Recipe 回放与重构前成交对齐
- 参数指纹预检（Dummy Context Check）能打出 `recipe=` 指纹
