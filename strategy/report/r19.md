# v1.3 加仓后重置回吐峰值（对照 v1.2）

v1.2 加仓净多 +1,451，但 7/16、11/11 是「刚加完就被 giveback 整仓洗出」。不是入口问题。

## 机制

回吐条件是：`(收盘最高 - 成本) / 成本 >= 1.5%` 且价格相对收盘最高回撤 `>= 0.8%`。  
加仓后均价下降，**第一笔的收盘最高原样保留**，峰值浮盈被抬高，很小的回落就能满足 0.8%。

| 日 | 加仓后均价 | 继承峰值时 | 实际 |
| :--- | ---: | :--- | :--- |
| 7/16 | 1.461 | 上午加在 1.483（当时已 +3%），14:30 `giveback` 整仓 +1,185 | 当日洗出，后面 7/21～29 只能重新开 |
| 11/10 | 1.616 | 次日 11:00 相对旧高回吐，整仓 +1,564，下午再开一笔 +547 | 两段切段合计略差于 v0.9 |

10/24、7/24 加完后又走出新高，重置峰值也不会挡这两笔的后续出场。

## v1.3 只改这一刀

| 因子 | v1.2 | v1.3 |
| :--- | :--- | :--- |
| 开仓 / 硬止盈 / 回吐宽度 | 同 | 同 |
| 加仓条件 | 浮盈 ≥1.5% 后再出买点 | 同 |
| 加仓成交后峰值 | 继承第一笔 `hold_close_peak` | **重置为加仓价**（`SCALE_RESET_PEAK`） |
| `hold_max_ret` | — | 只升不降（不让 stall 误砍已冲过高的仓） |

预期：7/16、11/11 不再因旧峰值当日/次日整出；10 月、7 月末赢家应还在。合计应高于 +8,968 才算这刀有效。不保证 30%（空窗仍是 `h1_skip`）。

覆盖后日志应有 `Ma15 v1.3 init` 且 `scale_reset_peak= True`，加仓成交附近有 `scale peak reset`。
